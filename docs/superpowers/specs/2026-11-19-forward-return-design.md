用户报告：去厕所到达后回起点时车头不转、倒着返程，前置深度相机不能覆盖返程行进方向。目标是先转向、确认朝向再前进，不能把“已下发转向”当成已完成转向。
所有写入限定在 /home/nvidia/guide_robot/learn/learn2_Z；厂家 SDK、地图、轨道和系统配置只读。不得启动实机运动验证。已有 README.md、tour_chat.py、mic_asr.py 的麦克风改动属于用户，保留且不混入修复提交。

## 证据
基准 93c6eea，当前 HEAD 4646820。独立 Standards / Spec 审查比较 git diff 93c6eea...HEAD。
现有 _goto 直接调用 move_to_locations_poi，没有出发转向。只读 GET 返回所有 POI yaw=0；轨道 1003 各段朝向基本与去程一致。SDK 轨道导航接口没有公开的“仅前进”参数，因此不能保证一次掉头能覆盖轨道内后续朝向指令。固定朝向是候选根因，尚未实机复现厂家规划过程。

## Approaches
1. 原地掉头后继续原轨道：改动少，但轨道自身的姿态仍可能让车辆恢复固定朝向，无法可靠满足需求。
2. 项目内前向导航（推荐）：使用位置与目标计算行进朝向，原地转向并验证实测 yaw，再使用带动态目标朝向的点对点规划；监测位置变化相对车头的投影，确认倒退时立即取消任务并报错。点对点规划的实际路线可能与固定轨道不同。
3. 修改底盘轨道姿态或创建反向轨道：可能保留精确轨迹，但会写入项目外的底盘数据，不在授权范围内，不采用。
以上推荐由实现者提出，尚待用户确认。

## 推荐实现范围
- 默认前向导航模式：去程、返程及绕行后重新导航共用朝向准备流程，防止只修一个语音指令分支。显式记录所使用的导航模式；前向模式不再下发固定朝向轨道任务。
- 基于当前定位和目标坐标计算 yaw；使用 SDK move_by(move_mode=1, distance=0, direction=相对角度) 原地转向，等完成后再次读取定位验证角度。定位/朝向不可用或转向失败则不下发平移任务。
- 前进任务用动态 yaw，轮询位姿变化，达到明确倒退判据时取消任务。轮询式监测存在采样延迟，不能宣称底盘层绝不产生反向速度；若固件仍坚持倒退则停车并记录证据，不无限重试。
- 深度帧记录接收时间和消息时间；转向后只允许使用新视角的有效新帧进行绕行判断，相机中断或帧过期时不放行绕行。确保独立 nav_route 入口也能处理深度订阅回调。
- 净空不足时保留停止等待流程，在原导航期限内观察障碍解除再恢复，超时明确失败。保留 AEB。
- 前置深度相机不覆盖车后，也不保证完整覆盖侧移扫掠区域；本修复不把左右图像距离当作完整侧向防碰撞保证，不增加后方传感能力。
- 只做与上述缺陷相关的调整；重复配置等纯维护性重构暂缓。
